# property-notice-60 实验记录

这是 Pack C 的主数据集。原来的 `property-notice`（30 篇文档、18 条查询）保持不动，
作为试点基线；这里单独扩到 60 篇文档、30 条查询，旧数字不覆盖。

## 数据

- 公告 20 篇（P001-P020）：停水、停电、电梯检修、燃气检查、消防、门禁、摄像头、绿化、垃圾、北门开放。
- 工单 24 篇（T001-T024）：下水道、漏水、电梯异响/按钮/门、路灯、门锁、空调、地锁、渗水、道闸、楼道灯、返味。
- 费用 6 篇（F001-F006）：两个季度的物业费、两笔维修基金、两次停车费调整。
- 通知 10 篇（N001-N010）：业主大会、失物、走失宠物、高空抛物、电动车充电。

查询 30 条，其中 9 条有多个相关文档（例如 `摄像头坏了` 同时对应 B 区和 C 区摄像头，
`维修基金怎么分摊` 同时对应 6 号楼和 7 号楼）。新增的 12 条查询刻意放了近邻干扰：
`西门路灯坏了` 对 `东门路灯不亮`，`北门道闸识别失败` 对 `南门道闸`，
`黑猫走失` 对 `橘猫走失`，`4号楼高空抛物` 对 `2号楼高空抛物`。

## BM25

```bash
npm run -w @book/lab-02-sparse-bm25 eval -- --scenario property-notice-60 --label sparse-bm25-60
npm run -w @book/lab-02-sparse-bm25 sweep -- --scenario property-notice-60
```

`eval`（k=5，k1=1.5，b=0.75）：Recall@5 0.967，MRR 0.878，nDCG@5 0.898。

30 条查询里只有 `污水倒灌怎么办` 完全没命中。它和所有文档都没有字面交集：
查询切出来是 `污水`、`水倒`、`倒灌`，文档里写的是 `下水道堵塞`、`地漏返水`、`管道返味`。
BM25 返回空列表，这是词法检索的硬边界。

其余 RR 小于 1 的查询：

| 查询 | RR | 第一次命中的位置 | 现象 |
| --- | --- | --- | --- |
| `3号楼停水` | 0.500 | 第 2 位 | P010（6 号楼清洗水箱，21 token）排在 P001（3 号楼主管道维修，33 token）前 |
| `摄像头坏了` | 0.333 | 第 3 位 | N004、N009 是"加装摄像头"的通知，含 `摄像头` 但不含"坏"；真正的 P016 在第 3 位 |
| `电动车能上楼充电吗` | 0.500 | 第 2 位 | N010（充电棚断电）含 `充电`，N005（禁止入户充电）在第 2 位 |
| `楼道灯一直闪` | 0.500 | 第 2 位 | T022（4 号楼楼道灯不亮）因更短排第一，T010（3 号楼持续闪烁）第二 |
| `下水道返味` | 0.500 | 第 2 位 | T001 命中 `下水`/`水道`，T011/T023 命中 `返味`；T001 先出 |

`sweep`（k1 ∈ {0.5, 1.0, 1.5, 2.0} × b ∈ {0, 0.25, 0.5, 0.75, 1.0}）：

- Recall@5 全部是 0.967，参数不改变"能不能搜到"。
- MRR 只随 b 变：b=0 时 0.950，b=0.25 时 0.894，b≥0.5 时 0.878；k1 从 0.5 到 2.0 没有改变排序。
- b=0 把 `3号楼停水`、`摄像头坏了`、`楼道灯一直闪` 都拉回第 1 位；
  `下水道返味` 仍是第 2，`污水倒灌怎么办` 仍然为空。

也就是说，长度归一化能修正"短文档占便宜"，但修不了同义词缺口。

## 五种检索方法

```bash
npm run -w @book/lab-01-retrieval-pipeline eval -- --scenario property-notice-60 --k 5 --label five-methods-60-k5
npm run -w @book/lab-01-retrieval-pipeline eval -- --scenario property-notice-60 --k 3 --label five-methods-60-k3
```

k=5：

| 方法 | Recall | MRR | nDCG |
| --- | --- | --- | --- |
| BM25 | 0.9667 | 0.8778 | 0.8985 |
| Dense | 0.7333 | 0.5622 | 0.5910 |
| Hybrid-RRF | 0.9000 | 0.8178 | 0.8248 |
| Hybrid-Weighted | 0.9167 | 0.8194 | 0.8364 |
| Hybrid-RRF+Rerank | 0.9500 | 0.8511 | 0.8659 |

k=3：

| 方法 | Recall | MRR | nDCG |
| --- | --- | --- | --- |
| BM25 | 0.9333 | 0.8778 | 0.8809 |
| Dense | 0.6000 | 0.5389 | 0.5335 |
| Hybrid-RRF | 0.8333 | 0.8111 | 0.7943 |
| Hybrid-Weighted | 0.8833 | 0.8111 | 0.8196 |
| Hybrid-RRF+Rerank | 0.9167 | 0.8444 | 0.8492 |

这个结果和试点版不一样：试点里 BM25 是 1.000，混合方法 0.9444，差距还能接受；
扩到 60 篇后，BM25 仍是 0.9667，混合方法全部低于 BM25。
原因不是融合公式写错，而是 Dense 这一侧太弱：`nomic-embed-text` 是英文模型，
中文语义匹配只有 0.7333（k=5），融合时把 BM25 的正确答案挤下去了。
Rerank 能把 RRF 从 0.9000 拉回 0.9500，但仍没有超过纯 BM25。

`污水倒灌怎么办` 在五种方法里全部是 0 命中。BM25 没有字面交集，
Dense 返回的是 P001（主管道维修停水）、T014（厨房水管爆裂）这类"和水有关"的文档，
没有一篇是地漏返水或下水道堵塞。这说明：当两个检索器都找不到时，融合也变不出来。

`摄像头坏了` 也是一个典型：BM25 的第 1、2 位是 N004、N009（高空抛物通知里提到加装摄像头），
Dense 直接返回 N010、T010 等无关文档；RRF 和 Weighted 都没有把 P016 拉进前 5，
只有 Rerank 把 P016 放到第 5 位。字面重叠在这里反而变成了噪声。

## ANN 索引（lab 03）

```bash
npm run -w @book/lab-03-dense-ann compare -- --scenario property-notice-60 --k 10 --label dense-ann-compare-60
```

60 篇文档、768 维、k=10：

| 索引 | 建索引(ms) | 单查询(ms) | Recall@10 | miss |
| --- | --- | --- | --- | --- |
| Exact | 0.06 | 0.059 | 1.000 | 0 |
| ANNOY | 1.44 | 0.049 | 1.000 | 0 |
| HNSW | 20.40 | 0.162 | 1.000 | 0 |

三个索引在这个规模上都没有丢结果。精确搜索单查询 0.059ms，已经比 HNSW 快；
ANNOY 略快，但建索引多花 1.4ms。也就是说，60 篇文档还没有到需要 ANN 的规模。

这个结果要和上面的 Dense 指标分开看：ANN 的 Recall@10 是"相对精确搜索"的召回，
只说明索引没丢候选；Dense 相对标注的 Recall@5 只有 0.7333，说明嵌入模型本身没找对。
索引近似误差和表示误差是两件事。

更大的合成向量对比、`n_trees` / `ef_search` 扫描见 `v2/labs/03-dense-ann/README.md`。
那里的 5,000 条 × 768 维数据上，Exact 单查询 15.405ms、ANNOY 0.301ms（Recall 0.887）、
HNSW 0.489ms（Recall 0.993，建索引 16.8s）。合成向量只测索引，不代表真实嵌入分布。

## 结论

- 在小规模中文语料上，BM25 仍是强基线；不要默认"混合一定比稀疏好"。
- 长度归一化 b 对短文档偏置很敏感；b=0 在 30 条查询上把 MRR 从 0.878 提到 0.950。
- 英文嵌入模型不能直接拿来当中文语义检索；Dense 的失败会通过融合传染给混合方法。
- 同义词缺口（`污水倒灌` vs `地漏返水`）不是调 k1/b 能解决的，需要换嵌入模型、查询改写或人工同义词表。

## 局限

- 30 条查询、60 篇文档仍然是小样本；Recall 的 0.033 差距只对应一条查询。
- 查询和标注由我一个人完成，没有第二人复核；多文档查询的相关性判断有主观成分。
- 嵌入模型是英文模型，Dense 的数字不能代表中文嵌入模型的水平。
- 所有数字只在这个数据集和当前参数下成立，不外推到其他语料。
