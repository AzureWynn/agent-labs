# pet-clinic-memory

## 用途

Pack A（用户记忆）的主数据集。目标是观察 ADD-only 记忆在反复复诊对话里如何堆积重复，以及规则去重后还能不能检索到正确事实。

## 结构

```text
scenario.json
├── name: "pet-clinic-memory"
├── note
└── users[5]
    ├── id / owner
    ├── pet { name, species, age }
    ├── facts[8]       # 规范事实，带 id 和 tags
    ├── rounds[30]     # 用户说法 + 助手回复
    └── queries[6]     # 查询 + expectedFactIds
```

- 5 位用户：u01 王女士/花花、u02 李先生/豆豆、u03 张阿姨/咪咪、u04 陈先生/球球、u05 刘女士/糖糖。
- 每位用户 30 轮、8 条事实、6 条查询。
- 合计 150 轮、40 条规范事实、30 条查询。

## 事实设计

每位用户 8 条：

| id | 内容 | 例子 |
|---|---|---|
| f1 | 主人 | 用户是王女士 |
| f2 | 宠物 | 用户养了一只猫，叫花花 |
| f3 | 年龄 | 花花今年3岁 |
| f4 | 健康 | 花花对鸡肉过敏 |
| f5 | 日程 | 花花下次疫苗是5月10日 |
| f6 | 电话 | 用户电话是13800001111 |
| f7 | 地址 | 用户住在3号楼2单元 |
| f8 | 照护 | 花花有轻微牙结石，建议半年复查 |

## 轮次设计

30 轮 = 8 条事实 × 3 轮 + 前 6 条事实各再加 1 轮。

- 每 8 轮循环一次，避免同一事实连续出现。
- 每条事实有 4 种说法：3 种用于循环，1 种用于额外补充。
- 说法保留宠物名、日期、数字和否定词，但句式不同，用来触发近似重复。
- 助手回复只做确认，不重复事实，避免把抽取难度降得太低。

## 查询设计

每位用户 6 条查询：

| 类型 | 例子 | expectedFactIds |
|---|---|---|
| 宠物名 | 我家猫的名字 | f2 |
| 年龄 | 花花今年几岁 | f3 |
| 健康 | 花花对什么过敏 | f4 |
| 日程 | 花花下次疫苗什么时候 | f5 |
| 电话 | 电话是多少 | f6 |
| 照护 | 花花牙结石要注意什么 | f8 |

电话查询用“电话是多少”而不是“王女士电话”：后者会把“用户是王女士”排到电话记忆前面，是词项打分的实体+属性歧义。这个反例保留在 `core-memory` 的 `retrieval.test.ts` 里，不作为 Recall 的计分查询。

## 生成

```bash
npm run -w @book/lab-04-user-memory generate
```

生成器在 `v2/labs/04-user-memory/src/tools/generate-scenario.ts`。默认拒绝覆盖；确实要改数据时加 `--force`。改完场景后，旧的 `runs/` 仍然保留，不要覆盖。

## 结果

抽取、去重和检索结果见：

- `v2/labs/04-user-memory/README.md`
- `v2/labs/04-user-memory/runs/pet-clinic-memory/2026-10-21/memory-gemma4-batch5-dedup3.json`
